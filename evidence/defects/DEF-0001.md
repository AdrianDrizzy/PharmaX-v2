## Root cause — proven, not inferred

Two independent branches each introduced a type family into
`PharmaX.Application.Finance`, **in different files**:

| Branch | File | Shape |
|---|---|---|
| `3a33832` ("Charge the patient accounts…") | `Finance/LedgerService.cs:43` | `JournalLineDto(string AccountCode, decimal Amount, …)` |
| `fe6d147` ("main changes") | `Finance/DayEndPostingService.cs:11` | `JournalLineDto(int LineNo, string AccountCode, …)` — **note the extra `LineNo`** |

Because the two declarations live in **different files**, Git saw no textual
conflict and auto-merged both sides. The C# compiler sees one namespace with two
records of the same name and different arity. The same union happened to
`AccountingOptions` inside `PharmaXOptions.cs`, which the merge duplicated
outright (two `AccountingOptions` class bodies, two `Accounting` properties).

Declaration counts at each merge parent, which prove the merge is the culprit:

| Commit | `AccountingOptions` decls | `JournalLineDto` in `LedgerService` | `JournalLineDto` in `DayEndPostingService` | Compiles |
|---|---|---|---|---|
| `37ac703^1` = `3a33832` | 1 | 1 | 0 | ✅ clean |
| `37ac703^2` = `fe6d147` | 1 | 0 | 1 | ✅ clean |
| **`37ac703` (the merge)** | **2** | **1** | **1** | ❌ **broken** |
| `8c1813e` (HEAD, PR #1 merge) | 2 | 1 | 1 | ❌ broken |

**Both parents are clean. The merge resolution at `37ac703` is the defect**, and
PR #1 (`8c1813e`) carried it onto `main` unchanged — meaning `main` has never
built since that merge landed.

## Remediation note (not applied)

Per Authority rule 3 the agent has **not** modified source. The fix is a
merge-resolution decision that belongs to the development team, not to QA,
because the two `JournalLineDto` shapes differ semantically — one carries
`LineNo` and one does not, so choosing between them is a design call about
whether a journal line is positionally identified. Resolving it by deleting
either declaration at random would silently change the shape of posted journal
data, which ACC-001…009 and TC-14 depend on.
